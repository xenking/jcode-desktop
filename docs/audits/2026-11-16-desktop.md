# Аудит Jcode Desktop от 16 ноября 2026

Цель аудита была проверить рискованные пути исполнением, исправить доказанные дефекты и сохранить пользовательские окна и данные. Проверены конфигурация, конкурентные обновления, доставка account snapshots, session/server routing, recovery, reload и отображение результатов инструментов.

## Подтверждено и исправлено

### 1. Сохранение настроек ослабляло права приватного конфига

`crates/jcode-desktop-ui-core/src/config.rs`, `persist_value_with_header`.

Red-тест `persisting_preferences_preserves_private_config_permissions` получил mode 0644 вместо исходного 0600. Предсказуемый временный файл создавался с правами по умолчанию и заменял исходный файл. Это могло открыть содержимое конфига другим локальным пользователям при доступных родительских каталогах.

Исправление использует новый файл `NamedTempFile` в том же каталоге и сохраняет существующие permissions. Коммит `8efc4b8`.

### 2. Временный symlink позволял перезаписать посторонний файл

Тот же путь конфигурации.

Red-тест `persisting_preferences_does_not_follow_a_stale_temporary_symlink` создал ссылку `config.toml.tmp` на отдельный файл. Сохранение настроек изменило посторонний файл вместо сохранения его исходного содержимого `untouched`.

Исправление пишет через дескриптор уникального временного файла и атомарно сохраняет его. Тест теперь проверяет неизменность постороннего файла и корректность конфига. Это доказанная порча данных при наличии такой ссылки, не доказанное повышение привилегий. Коммит `8efc4b8`.

### 3. Успешные конкурентные изменения настроек терялись

Тот же путь конфигурации.

Red-тест `concurrent_preference_edits_keep_every_successful_update` запустил 16 writers через barrier. Все вызовы завершились успешно, но не все записанные ключи сохранились.

Исправление держит OS file lock на всём read/modify/persist и оставляет атомарную замену файла. Green-проверка сохраняет все 16 обновлений и посторонние TOML-данные. Коммит `b4b5ac7`.

### 4. Новое окно могло пропустить завершившееся обновление аккаунтов

`crates/jcode-desktop-harness/src/accounts.rs`, `Poller::subscribe` и `Poller::publish`.

Red-тест `concurrent_subscription_observes_the_latest_published_snapshot` завершил подписку и публикацию конкурентно. На первой итерации подписчик получил старый пустой snapshot. Получено `None`, ожидалось `Some("fresh")`. Окно могло показывать устаревшее состояние до следующего периодического poll.

Исправление объединяет latest и subscribers в один `Mutex<PollerState>`. Regression выполняет 1024 конкурентных подписки/публикации. Полный harness suite прошёл 160 тестов, четыре live-зависимых теста остались ignored. Коммит `0a3af8b`.

## Доказательства и границы blast radius

Критическое условие безопасности config fix проверено исполнением. После сохранения mode 0600 остаётся 0600, посторонний symlink target не меняется, unrelated TOML сохраняется и ни одно успешное конкурентное обновление не теряется. Проверены реальные production-функции с временными файлами. Отдельный multi-process стресс не выполнялся.

Критическое условие account fix также проверено исполнением. После завершения конкурентных subscribe/publish последнее полученное состояние не старее опубликованного. Использованы реальные методы Poller без провайдера и credentials. OAuth этим не проверен.

Дополнительно исправлены устаревшие regression tests. Remote test больше не предполагает FIFO относительно асинхронного Cancel, workflow tests изолируют первые остановки, preview tests проверяют типизированный RuntimeError с исходным сообщением, GPUI edit-preview test получает настоящий headless render frame. Продуктовое поведение эти изменения не меняют. Коммит `f501ad9`.

На shipped Desktop `0a3af8b` с clean origin SDK `49fb945` буквальные core recipes дали 21 config, 27 login UI, 10 account health, 13 recovery, 3 restart и 9 host reload passes. Python safety suite прошёл 16 тестов.

Общий workspace gate дал 2299 passed, один failed и 20 ignored. Единственное падение `host::resources::tests::terminal_eof_waits_for_descendants_and_buffered_tail` получило пустой вывод вместо `trailing-output-after-shell-exit`. Этот отдельный PTY slice передан координатором другому исполнителю. До его интеграции общий gate нельзя называть зелёным.

UI clippy завершился успешно с существующими предупреждениями. Строгий core/harness clippy с `-D warnings --no-deps` прошёл на финальной паре Desktop/SDK. Запуск строгого clippy вместе с dependencies обнаружил существующий `map_identity` в `jcode-desktop-model/src/global_search.rs`, не связанный с этими изменениями.

## Неподтверждённые риски по приоритету

1. **Lifetime auth poller при reload.** `accounts.rs::shared_poller` запускает бесконечный поток, а host сохраняет предыдущие поколения библиотеки. Гипотеза о накоплении poller-потоков после reload имеет среднюю вероятность и высокий накопительный расход. Нужен private dynamic-reload стресс с измерением потоков и subprocess counts. Не воспроизведено.
2. **Поздний Cancel относительно следующего prompt.** В `harness.rs` Cancel исполняется асинхронно. Перестановка wire requests подтверждена тестовым ожиданием, но отмена неправильного пользовательского turn не доказана. Вероятность пользовательского эффекта неизвестна, цена высокая. Нужен управляемый fake-server сценарий с задержанным Cancel и двумя turn identities.
3. **Зависший auth subprocess.** `accounts.rs::fetch` ожидает `Command::output` без видимого timeout. Гипотеза о замороженном account feed имеет среднюю вероятность при зависшем CLI и умеренную цену. Нужен отдельный child-process repro с зависающим companion executable. Не запускался.
4. **Предсказуемые временные имена других persistence writers.** `workspace_recovery.rs::write` и `workspace_restart.rs::write_atomic` требуют отдельной проверки symlink/ownership. Цена возможной порчи recovery state высокая, вероятность без подтверждения неизвестна. Config repro нельзя автоматически переносить на эти writers.

Это очередь проверок, не дополнительные findings. В этом worker-сеансе nested swarm запрещён, поэтому независимая multi-model панель interrogate здесь не выполнялась. Ни один неподтверждённый риск не исправлялся как установленный дефект.

## Карта верификации

Один проход maintain-verification-skill выявил отсутствующие auth, persistence и reload. Они добавлены вместе с проверенными headless recipes и явными native-control gaps. Индекс содержит ровно восемь feature files, относительные ссылки проверены. Коммит `eade2fa`.

Полный live maintenance имеет outcome blocked. Linux-only workspace/terminal journeys недоступны на macOS без Xvfb/xdotool. Live OAuth, process-level relaunch и private dynamic-library reload также остаются gaps. Наличие unit tests не превращает их в live passes.

Принцип Model the Domain определил единый PollerState. Принцип Prove It Works определил red-first regression tests и проверку настоящего native артефакта вместо одной успешной сборки.
